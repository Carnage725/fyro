# Test notes: fyro v0.1 (release pass)

## Contract (from PLAN.md / BUILD_PROMPT.md, phases 0 to 9 and 6.1)
The contract is the phase prompts in `BUILD_PROMPT.md` plus the locked decisions in `PLAN.md`. The rules most often attacked:
- **Errors:** bad structure is an error that names the file, app or field and says how to fix it.
- **Input:** any input the API accepts can be stored. Bad input is a 4xx, never a 500.
- **Models:** `write_only` never leaves the server; `read_only` is never accepted.
- **Migrations:** a migration never fails on a table that already has rows.
- **Sessions:** a request commits before its response; a 4xx/5xx or an exception rolls back.
- **Permissions** are checked before row lookup (no id enumeration). Logout and deactivation end sessions immediately. Cookie writes need the CSRF header.

## Attacks tried
- **Each phase's checklist:** every item in `test.md`'s attack checklist for phases 1 to 9 has a test, apart from the gaps listed below.
- **Property tests:** Hypothesis (`tests/test_properties.py`, `tests/test_properties_schema.py`) checks four invariants:
  - anything `Create` accepts can be stored;
  - `PATCH` changes only the fields sent;
  - pages cover every row exactly once;
  - `Read` never contains `write_only`.

  It also checks that query parameters, path ids and search never give a 500.
- **Test order:** pytest-randomly, 5+ full runs in random order, plus explicit seeds.
- **Strict run:** `PYTHONASYNCIODEBUG=1 pytest -W error`.
- **Real database and real processes:** Postgres 16, 17 and 18. The schema is built through the real `migrate`. The end-to-end CLI test drives real subprocesses and a real server.
- **Versions:** Python 3.12.13, 3.13.12 and 3.14.3 (full suite each).
- **Browser:** the admin was driven in headless Chromium (light and dark), under a strict CSP.

## Bugs found
| Bug | Found by | Status |
|---|---|---|
| Adding a NOT NULL field with a default to a table with rows failed in `migrate` (`NotNullViolationError`) | attack checklist, reproduced at the phase 7 gate | fixed (phase 6.1) |
| `fyro.auth` could not load: models registered before their app was recorded; failed in both install orders | phase 8 spike | fixed (three-pass loader) |
| `User.email` showed as a textarea (no `max_length`) | phase 9 gate screenshots | fixed (`max_length=254`) |
| NUL characters and lone surrogates in text gave a 500 | property tests | fixed (schemas reject unstorable text) |
| Integers outside `INTEGER`/`BIGINT` range gave a 500, in bodies, filters and path ids | property tests | fixed (range validator) |
| A NUL character in `?search=` gave a 500 | property tests | fixed |
| FastAPI's default 422 echoes the input; a lone surrogate in it made the 422 itself a 500 | property tests | fixed (ASCII-escaped 422 handler) |
| The new range check silently replaced a user's own `Field(ge=...)` | existing unit test | fixed (validator instead of `Ge`/`Le`) |
| A field named `limit`/`offset`/`search`/`order_by` clashed with list parameters | attack checklist | fixed (startup error) |
| A unique field with a constant default on a table with rows would fail its migration | attack checklist | fixed (refused) |
| `T \| None` changed to `T` failed when rows held NULL | attack checklist | fixed (fill or refuse) |
| CLI printed a full traceback for database errors | attack checklist | fixed (one line, password masked) |
| The process-wide engine leaked between tests, so a later test used the wrong database | pytest-randomly | fixed in tests (engine reset) |
| The end-to-end test leaked a pipe file handle | `-W error` | fixed in the test |

## Known gaps (deliberately not covered yet)
- **Type checking:** no type checker (mypy or pyright) is configured.
- **Mutation testing:** no automated tool (mutmut); only the 37 hand mutants above.
- **Concurrency:**
  - two concurrent `migrate()` runs;
  - two concurrent `PATCH`es or unique `POST`s;
  - session isolation under `asyncio.gather`;
  - client disconnect or cancellation mid-request.
- **Migration edge cases still open** (from `test.md`): Decimal/date/UUID constants, quotes in Enum values, a default longer than the column, timezone of `date.today`, an error raised mid-`migrate`.
- **Windows** is untested. The CI workflows have not run on GitHub yet; they were checked by running their commands locally.
- **No load or performance testing,** no login rate limiting (out of scope for v0.1), and the admin requires JavaScript.
